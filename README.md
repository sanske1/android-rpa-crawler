# Android RPA 列表数据采集

基于 **adb + Android 无障碍服务（uiautomator）** 的 RPA 采集框架：自动滚动 App 列表页，
逐屏读取屏幕上已渲染的**无障碍文本树**，解析、去重、清洗成结构化数据。

**纯标准库，零第三方依赖**（Python 3.7+ 即可）。

---

## 为什么说这是"低风险"方案

这里说的"低风险"，指的是**不对目标 App 本身做任何对抗性操作**：

| 不做的事 | 说明 |
|---|---|
| 不破解签名 | 不碰接口签名、不做请求重放 |
| 不逆向 / 不注入 | 不用 frida、不 hook 进程、不 dump 内存 |
| 不抓包 | 不设代理、不装证书、不改流量 |
| 不绕访问控制 | 只采集**当前已登录账号下肉眼可见**的内容 |

它做的事情只有一件：**读屏幕上已经画出来的文本**。数据来源是 Android 无障碍服务
（`AccessibilityNodeInfo`）暴露的视图层级——文本是原始字符串，一字不差，与图像识别无关。

> ⚠️ "低风险"不等于"无风险"。多数平台的服务条款对自动化访问有约束，
> 使用者需自行确认合规。详见文末免责声明。

## 工作原理

```
回顶 → 循环 { dump UI 树 → 解析 → 去重累积 → 滑动 → 等待 }
              直到「连续两次整屏签名完全相同」或达到上限
```

- **取屏**：`adb shell uiautomator dump` + `cat` 拉回 XML
- **双模式解析**（互为补充）
  - *严格模式*：以「时间行」为锚点，在有限纵向范围内配昵称/正文/规格行，字段完整
  - *宽松模式*：不看锚点，直接收集中文占比达标、长度合适的文本，产量更高
  - 两者按正文前若干字合并去重，严格记录为宽松记录补齐缺失字段
- **到底判定**：整屏 `(bounds, text)` 排序后取 md5；连续两次相同即停止
  （不用"连续 N 屏无新增"——会因加载延迟过早停止）
- **清洗**：按规则剔除页面噪声（统计数字、促销条、规格串、参数行、榜单徽章等）

## 快速开始

```bash
# 1. 确认设备已连上、并停在目标列表页
adb devices

# 2. 验证环境（不滚动，只解析当前一屏）
python uiparse.py --probe --out ./capture

# 3. 正式采集
python crawler.py --out ./capture --sleep 2.6

# 4. 实时看采集过程
python watch.py ./capture

# 5. 查看已落盘的数据
python view.py ./capture 20
```

### 常用参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--out` | `capture` | 输出目录 |
| `--adb` | 自动探测 | adb 路径；也可用环境变量 `ADB` |
| `--sleep` | 2.6 | 每屏间隔秒（放慢可降低被拒风险） |
| `--max-screens` | 100000 | 最大滑动屏数 |
| `--max-comments` | 不限 | 抓够这么多条就停 |
| `--no-top` | — | 不从顶部开始，从当前位置续 |
| `--no-ff` | — | 续跑时不做"回放追进度" |

## 断点续跑

**同一条命令反复执行即可**，不会重复、不丢进度：

```bash
python crawler.py --out ./capture --sleep 2.6
```

机制：

1. 每 10 屏把**累计滑动次数**写入 `progress.json`，同时增量落盘数据（原子写，断电不坏）
2. 下次启动：载入已有数据 → 读锚点 → **用完全相同的滑动手势回放 N 次**
   （滑动一次的距离是固定的，所以回放 N 次即回到第 N 屏）
3. 回放时**不解析**（跳过每屏 2.5 秒的 dump），省下大头时间
4. 最后一段改用常规步长**逐屏内容确认**，撞到新内容就回退几屏转入正常采集

> 为什么不是精确算位置：列表页的 UI 树里混着屏幕外节点，"本屏有哪些内容"读不准。
> 所以位置只能靠"滑动次数"这个确定量来对齐。

## 运行监控（为什么它不会闷头乱跑）

- **拦截信号扫描**：每屏扫 UI 里的验证码 / 操作频繁 / 网络异常 / 被踢登录（只认短文案，避免误伤用户内容）
- **logcat 过滤**：按关键词捞安全/风控相关日志（关键词可配置）
- **吞吐趋势**：`timeline.csv` 记录每屏新增条数——**速率突然掉下来通常就是被限流的第一个信号**
- **停止定性**：页面停住时会区分"自然到底""被拦""设备熄屏"，不会把熄屏误报成风控
- **掉线自愈**：设备 offline / 无线 adb 断开时自动重连

---

## 目标校验（避免两批数据混一起）

启动时读列表页顶部名称，与本目录 `product.json` 记录比对：

- 一致 → 继续
- **不一致 → 打印警告，自动改用新目录 `<原目录>__<页面名>`**，两批数据互不污染

名称比对是**宽松的**（页面顶部常显示"当前选中规格"而非页面名，同一目标滚动时会变）。

## 已知边界

- **拿不到**图片/视频内容（无障碍树里没有对应文本节点）
- 列表项里的长文本可能被 App 截断显示（结尾带"展开"），只能拿到可见部分
- 规则是**按页面版式调的**：换 App / 换版式需要调整 `uiparse.py` 里的噪声规则与字段识别
- 采集速度上限受 `uiautomator dump` 制约（一次约 2.5 秒），单设备约 0.16 屏/秒
